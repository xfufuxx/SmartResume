## 3. 通用测试约定

- **鉴权**：业务接口需在 Header 带 `Authorization: Bearer <access_token>`。
  获取：`POST /api/auth/login` → `data.access_token`。
- **错误码**：后端统一返回中文码（如 `RESUME_NOT_FOUND`、`FILE_TOO_LARGE`、`PARSE_BEFORE_OPTIMIZE`、`QUOTA_EXCEEDED`），前端 `lib/api.ts` 已归一化为字符串，不会崩溃。
- **AI 依赖**：`LLM_API_KEY` 无效时自动 Mock，**可无网联调 UI**（优化结果为占位，但流程跑通）。
- **任务状态**：优化为异步任务，状态机 `pending → processing → completed | failed | cancelled`；前端轮询，完成后弹对比弹窗。
- **取消语义**：`POST /api/optimize/async/{task_id}/cancel` → 任务中断、**不写半成品记录**、历史记录数不变。

### 4.4 AI 优化（核心链路，`/api/optimize`，前端 `/`）

| ID | 功能点 | 前置 | 步骤 | 预期 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| OPT-01 | 提交异步优化 | 已上传简历+岗位 | `POST /api/optimize/async` {resume_id,job_id} | 202，返回 `task_id`，状态 `processing` | P0 |
| OPT-02 | 快速优化（个人中心文本） | 已填文本 | `POST /api/optimize/quick` {resume_text,job_text} | 202，返回 `task_id` | P1 |
| OPT-03 | 轮询状态 | — | `GET /api/optimize/async/{task_id}` 周期轮询 | `processing→completed`，带 `result` | P0 |
| OPT-04 | **手动停止** | 优化进行中 | 前端点「停止优化」→ `POST /api/optimize/async/{task_id}/cancel` | 状态 `cancelled`；运行条消失、可重新操作；**历史记录数不变（无半成品）** | P0 |
| OPT-05 | 取消幂等 | 已取消 | 再次 cancel 同一 task | 200，不报错 | P1 |
| OPT-06 | 取消归属校验 | 他人 task_id | 用 B 账号 cancel A 的 task | 403/404，不越权 | P1 |

| OPT-08 | 差异算法不被误报 | 真实记录 | `微服务→微服务开发` 类改写 | 识别为「关键词细化」，不报「移除技能」 | P1 |
| OPT-09 | 渲染 PDF | 已完成 | `POST /api/optimize/render` {task_id,template} | 三档降级渲染，返回签名代理 URL | P0 |
| OPT-10 | 模板选择 | — | 切换 `TemplateSelector` | 渲染按所选模板 | P2 |
| OPT-11 | 未解析先优化 | 简历未解析 | 提交优化 | 400 `PARSE_BEFORE_OPTIMIZE` | P1 |
| OPT-12 | 配额超限 | 配额耗尽 | 提交优化 | 400 `QUOTA_EXCEEDED` | P2 |

## 5. 端到端主流程验收（核心链路）

按以下顺序走一遍完整链路（建议用演示账号，或先导入演示数据）：

1. 打开 `http://localhost:3000/` → 登录 `demo@smart-resume.com` / `Demo@123456` → 落地 `/dashboard`。
2. 进「优化」页 `/` → 从简历库选一份已解析简历 → 从岗位库选目标岗位。
3. 点「立即优化」→ 观察运行条出现、**已用时在走动**（实测应能走到数秒，非恒 0）。
4. **停止验证**：在优化进行中点「停止优化」→ 运行条立即消失、「立即优化」恢复可点、已选简历/岗位保留、不弹窗。
5. 再次点「立即优化」→ 等待完成（约 2–3 分钟）→ **自动弹出前后对比弹窗**，含：匹配度前后、变化摘要 chips、章节「修改前→修改后」对照（新增 `<mark>` 高亮、删除划线）。
6. 关闭弹窗 → 页面可继续操作。
7. 导出：点导出 PDF/Word → 浏览器下载文件，内容与优化结果一致。
8. 进 `/history` 查看本次记录（状态应为 `completed`，非 `cancelled`）。
9. 控制台检查：无 hydration 报错；`Failed to fetch RSC payload ... Falling back to browser navigation` 属 Next.js 预定回退噪声，非缺陷。

## 8. 已知风险与验证点

| # | 风险 | 验证点 |
| --- | --- | --- |
| 1 | `.env.example` 含真实密钥（已纳入版本控制） | 上线前轮换密钥、改为占位符、清理 git 历史 |
| 2 | `SECRET_KEY` 默认 `change-me-in-production` | 改后 JWT 不可伪造、AES 可解密 |
| 3 | 限流依赖 Redis，Redis 不可用抛错无降级 | 停 Redis 后限流接口是否优雅失败 |
| 4 | Celery 未接入，进程重启丢任务 | 优化中重启后端，任务状态是否合理 |
| 5 | 匹配度两口径混显（AI 92 vs 关键词 70→75） | 确认弹窗标「关键词匹配度」、大数标「职位匹配度」 |
| 6 | Windows 本机 `next build` 被 safe-delete 钩子拦截并清空 `.next` | 构建时注入 `CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=2000000`；`.next` 损坏先 `mv` 再重建 |
| 7 | AntD 两汉字按钮文案被插空格 | 自动化查找按钮用「字符间允许空白」正则，避免超时 |
| 8 | 演示数据部分 PDF 指向占位路径 | 验证「文件缺失/下载失败」分支不崩溃 |
