# 极简部署教程

> 新购的 Linux 实例（如学生算力包创建）可直接从第 1 步开始；只有当前实例是 Windows 且要废物利用时才需要第 0 步重装。

## 0. 重装系统（阿里云控制台）
实例 → 停止 → 更多 → 云盘和镜像 → 更换操作系统 → 选「Alibaba Cloud Linux 3.2104 LTS 64 位」→ 设 root 密码 → 开始更换 → 启动实例

## 1. 安全组放行端口
入方向最终只保留：80（0.0.0.0/0）；传代码前临时加 22（授权对象填自己 IP，传完删掉）
⚠️ 默认规则若自带「RDP 3389」「所有 ICMP」且对 0.0.0.0/0 开放，直接删除——Linux 实例用不到 RDP，日常管理用「启动远程会话...」，不开任何公网管理端口

## 2. 连服务器
推荐顺序（按省事程度）：

① 直接开 22 用 SSH（最省事，反正第 4 步传代码也要开）：安全组临时加 TCP 22（授权对象填自己当前 IP）→ 点「远程连接(SSH)...」或本地 `ssh root@121.40.191.169` → 传完代码、部署完成后删掉该规则
② 「启动远程会话...」（全程不开端口）：**首次使用需先开通「会话管理」服务**（一次性、免费）——点「远程连接(SSH)...」弹出的对话框里找「会话管理」页签点「立即开通」，或在控制台顶部搜索「会话管理」进入开通；成功后再回实例菜单点「启动远程会话...」→ root + 购机密码

## 3. 装 Docker（服务器上执行）
```bash
dnf install -y dnf-plugins-core
dnf config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
```
配镜像加速 + 构建期国内源（docker.io 直连大概率 502/超时；pip/npm/apt 同样慢，一次全配上）：
```bash
# ① 测哪个镜像站通（返回 401 = 通；超时 = 不通，换下一个）
timeout 15 curl -sI https://docker.m.daocloud.io/v2/ | head -1
# ② 把通的写进 daemon.json（备选 https://docker.1ms.run；ACR 专属地址需先在控制台开通容器镜像服务，部分账号不可用）
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io"]
}
EOF
systemctl daemon-reload && systemctl restart docker
docker pull python:3.12-slim
# ③ apt/pip/npm 国内镜像（Dockerfile 已内置；对早前上传的包在服务器上补打补丁）
cd /opt/smart-resume
sed -i '3i RUN sed -i "s|deb.debian.org|mirrors.aliyun.com|g; s|security.debian.org|mirrors.aliyun.com|g" /etc/apt/sources.list.d/debian.sources /etc/apt/sources.list || true' backend/Dockerfile
sed -i 's|RUN pip install --no-cache-dir|RUN pip install --no-cache-dir -i https://mirrors.aliyun.com/pypi/simple/|' backend/Dockerfile
sed -i 's|^RUN npm install$|RUN npm install --registry=https://registry.npmmirror.com|' frontend/Dockerfile
```
兜底（镜像站全不通时）：直接带源拉取再打标签，compose build 会用本地镜像不再联网——`docker pull docker.m.daocloud.io/library/python:3.12-slim && docker tag docker.m.daocloud.io/library/python:3.12-slim python:3.12-slim`（node:20-alpine、postgres:16-alpine、redis:7-alpine、nginx:1.27-alpine 同理）。

## 4. 传代码
本地 CMD 或 Git Bash 均可。⚠️ 两个要点：① 打包输出放到项目目录外，否则 tar 报「Can't add archive to itself」；② 排除本地 .env（含真实 Key，不上传，服务器上按第 5 步从模板重新生成）。scp 走 22，传完删掉该规则：
```cmd
tar --exclude=frontend/node_modules --exclude=frontend/.next --exclude=backend/.venv --exclude=__pycache__ --exclude=.git --exclude=backend/.env --exclude=docker/.env -czf D:\app.tar.gz .
dir D:\app.tar.gz
scp D:\app.tar.gz root@121.40.191.169:/root/
```
（首次 scp 问 yes/no 输 `yes`；密码输入时屏幕不动是正常的；`dir` 看大小应为几十 MB，若几百 MB 说明 node_modules 没排除干净）
服务器上执行：
```bash
mkdir -p /opt/smart-resume && tar -xzf /root/app.tar.gz -C /opt/smart-resume && cd /opt/smart-resume
```

## 5. 改配置（服务器上执行；把「你的强密码」「sk-你的千问key」「你的邮箱@qq.com」「你的授权码」换成真实值）
> 「你的强密码」= PostgreSQL 数据库密码，自己现编一个：只用大小写字母+数字+`-`/`_`，16 位以上；**不能含** `/ & ' \ @ : # ? %` 和空格（会破坏 sed 命令与数据库连接串），例 `Kx7m-Q2wR-9pLt-4vBn-8sTd`。只存在于服务器 docker/.env，日常备份恢复不用手输。
> 「sk-你的千问key」= 打开本地 `backend/.env`，复制 LLM_API_KEY 那行的值填进去（本地 .env 已按第 4 步排除，不会上传）。
```bash
cp docker/.env.production.example docker/.env
cp backend/.env.example backend/.env
sed -i 's/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=你的强密码/' docker/.env
sed -i 's|^NEXT_PUBLIC_API_URL=.*|NEXT_PUBLIC_API_URL=http://121.40.191.169|' docker/.env
sed -i "s|^SECRET_KEY=.*|SECRET_KEY=$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')|" backend/.env
sed -i 's/^LLM_API_KEY=.*/LLM_API_KEY=sk-你的千问key/' backend/.env
sed -i 's|^CORS_ORIGINS=.*|CORS_ORIGINS=http://121.40.191.169|' backend/.env
sed -i 's|^BACKEND_URL=.*|BACKEND_URL=http://121.40.191.169|' backend/.env
sed -i 's/^SMTP_USER=.*/SMTP_USER=你的邮箱@qq.com/;s/^SMTP_PASSWORD=.*/SMTP_PASSWORD=你的授权码/;s/^SMTP_FROM=.*/SMTP_FROM=你的邮箱@qq.com/;s|^SMTP_FROM_NAME=.*|SMTP_FROM_NAME=智能简历|' backend/.env
```

## 6. 启动（服务器上执行，首次 10~30 分钟）
```bash
docker compose --env-file docker/.env -f docker/docker-compose.yml up -d --build
curl http://127.0.0.1/health
```
显示 `{"status":"ok",...}` 即成功。

## 7. 访问
浏览器打开 `http://121.40.191.169`

## 8. 每天自动备份（服务器上执行一次）
```bash
mkdir -p logs
(crontab -l 2>/dev/null; echo "0 3 * * * cd /opt/smart-resume && bash scripts/backup_db.sh >> logs/backup.log 2>&1") | crontab -
```

## 9. 以后更新代码（本地改了 → 服务器生效）
本地重新打包并上传（命令同第 4 步，已排除 .env）：
```cmd
tar --exclude=frontend/node_modules --exclude=frontend/.next --exclude=backend/.venv --exclude=__pycache__ --exclude=.git --exclude=backend/.env --exclude=docker/.env -czf D:\app.tar.gz .
scp D:\app.tar.gz root@121.40.191.169:/root/
```
服务器上一条命令搞定（自动：备份数据库 → 存回滚点 → 覆盖代码 → 重建 → 健康检查）：
```bash
bash scripts/update_server.sh
```
只改了后端、想跳过前端那 2 分钟构建时：
```bash
bash scripts/update_server.sh /root/app.tar.gz backend celery_worker
```
说明：
- `backend/.env`、`docker/.env` 解压时自动排除，千问 Key / 数据库密码 / SMTP 配置原样保留
- uploads 卷（用户简历文件）和 pgdata 卷（数据）不受更新影响
- 表结构变更后端启动时自动迁移（create_all + 幂等 ALTER）；大改版若报「列不存在」，进容器补跑 `docker compose --env-file docker/.env -f docker/docker-compose.yml exec backend alembic upgrade head`
- 更新失败时按脚本打印的回滚命令操作，回滚点在 `/root/rollback/`

## 注意
- SMTP 不配 = 注册验证码只进后端日志：`docker compose --env-file docker/.env -f docker/docker-compose.yml logs backend`
- 22 端口只在上传代码/连接时临时开，用完删掉；日常管理用「启动远程会话...」（需先开通会话管理，不开端口）
- 以后更新代码：见第 9 节，服务器上 `bash scripts/update_server.sh` 一条命令
