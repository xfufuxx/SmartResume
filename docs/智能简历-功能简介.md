## 1. 产品定位与技术栈

**智能简历优化系统** 是面向求职者的一体化简历优化与求职管理 SaaS 平台：用户上传简历与岗位 JD → 系统通过 AI 解析、人岗匹配、ATS 兼容性检测、逐段优化 → 渲染为专业排版的 PDF/Word；并提供岗位库、投递（按钮文案按通道动态显示：邮件直接投递 / AI 帮你填写 / 前往招聘平台投递 / 记录这次投递，含邮件直投 / 官网表单 / 平台引导三类通道）、面试追踪（投递记录 / 面试进度 / 沟通消息）等闭环求职管理工具。

| 层 | 选型 |
| --- | --- |
| 前端 | Next.js 14（App Router）+ React 18 + TypeScript + Ant Design 5；图表 ECharts；请求 axios |
| 后端 | FastAPI（Python 3.12）+ Uvicorn；ORM SQLAlchemy 2.0（async）+ asyncpg；数据库 PostgreSQL 16（JSONB 承载半结构化字段） |
| 缓存 / 限流 / 任务状态 | Redis 7 |
| 鉴权 | JWT 双 Token（access 2h / refresh 7d，HS256） |
| 大模型 | OpenAI 兼容协议（视觉+文本同一 base），开发环境无 Key 时 Mock 兜底；`APP_ENV=production` 下不静默 Mock，显式报错可重试 |
| 文件安全 | 简历 PII 入库前 AES-256-CBC 加密；文件仅经 HMAC 签名代理 URL 访问，不挂载静态目录 |
| PDF 渲染 | Playwright → WeasyPrint → ReportLab 三档降级 |

## 3. 功能详细说明

### 3.1 主功能

#### 3.1.1 首页（数据洞察 / 行动中心）`/dashboard`
- **定位**：登录后落地页，聚合用户求职全景数据，并从「数据看板」向「行动中心」演进。
- **核心能力**：`GET /api/insights/overview?days=` 返回简历数、岗位数、优化次数、投递数、面试进度分布、近期活动等聚合指标（`days` 可缩放时间窗）。
- **今日求职行动**：基于真实数据推导的时间敏感提醒，置于普通建议之前——投递超 5 天无进展 → 去跟进；48 小时内有「待面试」→ 去准备（跳 AI 面试押题）；HR 近 3 天回复过 → 去回复；收藏未投递 → 去投递。
- **求职漏斗**：岗位库 → 收藏 → 已投递 → HR 回复 → 面试 → Offer 六级转化，自动标出转化最弱环节并给出对应行动建议（如回复率低 → 检查匹配度与关键词覆盖）。
- **关联**：数据来自简历 / 岗位 / 优化 / 投递 / 面试进度 / 沟通各模块真实记录，无模拟数据。

#### 3.1.2 简历优化（核心链路）`/`
- **定位**：系统主轴——「上传解析 → AI 优化 → 渲染导出」。
- **核心能力**：
  - 上传解析：选择简历文件（PDF/图片/Word），`POST /api/resumes/upload` 解析为结构化 `parsed_json`（`raw_text` 加密入库）。
  - 同步优化：`POST /api/optimize` 传入 `resume_id`+`job_image_id`+`template`，生成优化记录与 PDF。
  - 异步优化：`POST /api/optimize/async` 提交任务，`GET /api/optimize/async/{task_id}` 轮询状态，`cancel` 可中止。
  - **可靠任务队列保障（P0）**：任务状态持久化（Redis / DB），三层防悬挂——① **启动恢复**：Web 进程重启时自动把遗留的 pending/processing 任务判为 failed（提示「服务重启导致任务中断，请重试」），覆盖 AI 优化（Redis）、面试押题、批量优化（DB）三类；② **心跳超时兜底**：任务每次进度写入带 `updated_at` 心跳，轮询端点发现心跳超过阈值（优化/面试 10 分钟、批量按 3 分钟/岗位动态计算且下限 30 分钟）即判 failed，执行进程异常死亡也自愈；③ **执行器兜底**：后台协程异常逃逸时由 done-callback 落 failed 终态。用户永远能在有限时间内得到明确结果，不再无限等待。
  - 一键优化：`POST /api/optimize/quick` 从个人 `saved_texts` 直接优化（异步）。
  - 差异对比：`GET /api/optimize/diff?id1=&id2=` 两版本逐段 diff。
  - 在线编辑：`PUT /api/optimize/{id}/content` 人工微调结果。
  - **AI 修改逐条确认（P0）**：把「AI 直接产出」升级为「AI 建议 → 用户逐条确认 → 新版本」。`GET /api/optimize/{id}/changes` 将优化前后对比成**条/点级**变更清单（个人简介 / 技能关键词细化·新增·移除 / 工作经历逐条描述 / 项目经历，共 4 大类），每条含稳定 id、类型、前后文本；前端弹窗逐条呈现（前后高亮对照），支持**接受 / 拒绝 / 编辑后接受**（可编辑条目内联修改 AI 文案）+ 全部接受 / 全部拒绝；`POST /api/optimize/{id}/changes/apply` 以**原始简历为底**仅叠加被接受的变更，生成「人工确认版」新记录（`parent_record_id` 挂靠源记录 → 自动进入简历版本树），原优化结果保持不变；全拒绝 → 400。
  - **AI 事实核验（P0）**：每条建议附带**规则引擎**产出的事实核验标注（无额外 LLM 调用）——✅ 来源于原始简历 / ⚠ 原简历未提及此内容 / ⚠ 新增数字（列出具体数值，如 35%、4倍）/ ⚠ 新增技能（AI 推断）/ ⚠ 可能存在夸大表达（精通、主导、行业领先等强主张词，原文没有才标）；技能同源细化不误报；响应含 `warn_count`，前端顶部黄条汇总提示，帮助用户核对「哪些词是 AI 新增的、哪些数字是 AI 推断的」，降低美化过度带来的不信任。
  - 重新导出：`POST /api/optimize/{id}/reexport`。
  - 模板测试：`POST /api/optimize/test-template`。
  - 满意度：`POST /api/optimize/{id}/feedback`（1–5 分，单记录仅一次）。
- **规则分析**：`POST /api/analysis/resume` 纯规则聚合（匹配度 / 关键词 / ATS / 四维 / 建议），不耗 AI 额度。
- **精炼改写**：`POST /api/optimization/{id}/refine`（最多 3 次微调）。
- **导出**：`GET /api/export/optimize/{id}/docx`、`GET /api/export/resume/{id}/docx`。

#### 3.1.3 简历管理 `/resumes`
- **定位**：用户简历仓库，支持增删改查、收藏、设主简历、回收站。
- **核心能力**：上传、列表、统计 `GET /api/resumes/stats`、收藏切换、从源简历复制新建、`PUT /{id}/primary` 设主简历、`PUT /{id}` 改标题、批量删除（进回收站）、回收站列表 / 恢复 / 单条恢复、软删除。
- **简历版本树（P0）**：卡片菜单「版本树」→ `GET /api/resumes/{id}/version-tree`，以原始简历为根聚合完整版本谱系——原始版 → 各岗位 AI 优化版（`OptimizedResume.resume_id` 挂靠，含匹配度/目标岗位）→ 逐条修改/微调链（`parent_record_id` 自引用，可多级；**AI 逐条确认生成的人工确认版同构入树**）；前端以 AntD 树形图展示（默认全展开，标注「原始版 / 岗位优化版 + 匹配分 / 第 N 次修改」），并给出「N 个优化版 · N 次微调」摘要。
- **关联**：优化的输入来源；投递时可选简历；匹配 / 评分 / ATS 的对象；版本树以本模块为根贯通优化与微调记录。

#### 3.1.4 岗位库 `/jobs`
- **定位**：纯岗位仓库，只做岗位的增删改查、搜索、分类、收藏、预览与「一键投递入口」；**已剥离**投递状态 Tab / 流程统计 / 面试阶段列等过程字段（过程信息移入面试追踪）。
- **核心能力**：上传岗位图片并解析 `POST /api/jobs/upload`（`use_ocr` 可选）、仅解析不入库 `POST /api/jobs/parse-image`、分类枚举（公开 `GET /api/jobs/categories`）、搜索 / 分类过滤 `GET /api/jobs?q=&category=`、手动创建 / 批量导入、收藏、复制、回收站、设默认岗位。
- **关联**：优化的 JD 输入；匹配 / ATS / 评分的对照对象；一键投递的岗位源。

#### 3.1.5 我的（个人中心）`/profile`
- **定位**：账户与隐私设置。
- **核心能力**：`GET/PUT /api/user/profile`（昵称 / 职业状态 / 隐私同意）、`PUT /api/user/expectation`（求职意向：行业 / 职位 / 薪资 / 城市）、`POST /api/user/avatar`（头像，限 PNG/JPG/WEBP ≤5MB）、`PUT /api/user/privacy/agree`、`GET /api/user/export-data`（GDPR 导出）、`POST /api/user/sync-saved-texts` 与 `PUT /api/user/saved-texts`（简历/岗位文本同步到 saved_texts，供一键优化）。
- **关联**：投递时姓名 / 邮箱 / 电话自动从个人资料带出（招聘软件式，不重复填写）。

### 3.2 求职工具

#### 3.2.1 AI 面试押题 `/interview`
- **定位**：基于简历 + 岗位生成针对性面试题清单。
- **核心能力**：`POST /api/interview/generate`（`resume_id`/`job_image_id`/问题数，异步生成）、会话列表 `GET /api/interview/sessions`、详情、删除、`POST /api/interview/questions/{id}/bookmark` 收藏、`PUT /api/interview/questions/{id}/note` 保存答题草稿、`GET /api/interview/bookmarks` 跨会话题库。

#### 3.2.2 岗位匹配罗盘 `/match`
- **定位**：量化「简历 vs 岗位」契合度。
- **核心能力**：`POST /api/match`（单岗位匹配度）、`POST /api/match/rank`（一份简历 × 全部岗位排序，可选 `limit`）。

#### 3.2.3 ATS 体检 `/ats`
- **定位**：检测简历对 Applicant Tracking System 的友好度。
- **核心能力**：`POST /api/ats/check`（`resume_json` + 可选 `job_json`）。

#### 3.2.4 简历评分 `/scoring`
- **定位**：四维评分与岗位热度情报。
- **核心能力**：`GET /api/resume/{id}/score?job_id=`（四维评分，未解析报错）、`GET /api/scoring/jobs/trending?days=`（匿名岗位热度汇总；注意该路径不可置于 `/api/jobs/{job_id}` 之下，会被岗位详情路由遮蔽）。

#### 3.2.5 岗位能力测评 `/capability`
- **定位**：用户对目标岗位做能力自评（1~5 星），系统给出匹配度、逐维度强弱项分析、三阶段能力补步建议与「岗位匹配排行」，帮助用户了解自身比较适合的岗位。
- **与简历评分的区别**：简历评分是机器对简历的客观评分；本模块是用户对岗位能力的**自我评估画像**，两套数据相互独立。
- **岗位画像库**：`GET /api/capability/jobs`（关键词/分类过滤）、`GET /api/capability/categories`、`GET /api/capability/jobs/{id}`（每岗位含 **6~8 个专业核心考察点 + 7 项通识基础素质**，每维含衡量标准 desc、低分点评 low_tip、高分建议 high_tip、学习资源 resources、关键动作 actions）。系统内置 **20 个岗位画像**，启动时幂等播种（新标题插入；已存在内置岗位内容有变化时自动更新，用户自建同名岗位不覆盖）：
  - 技术岗：后端/前端/Java/Linux 开发、软件测试讲师、测试开发（SDET）、云计算、DevOps/SRE、嵌入式、软件驱动、汽车软件、软件质量、项目经理、数据分析师；
  - AI 岗（2026 招聘热门方向）：AI 产品经理、大模型应用开发工程师、算法工程师；
  - 设计/运营岗：UI/UX 设计师、新媒体运营专家。
- **维度设计原则**：以岗位 JD 要求全覆盖为目标，不刻意压缩考察点数量——每个维度对应一类真实、可独立考察的工作要求，项与项之间不重叠（无冗余灌水），合起来覆盖该岗位主要能力要求；单次测评 13~15 题、约 3~4 分钟。「问题尽可能少」的前提是要求不遗漏，二者冲突时以覆盖为先。
- **测评流程**：`POST /api/capability/assessments`（自评分数须与画像维度完全一致，缺项/多项 → 422；分数须为 1~5 整数；岗位不存在 → 404）→ 生成报告快照 + 写入站内通知（msg_type=job）。每题 1~5 星。
- **报告内容**（确定性规则引擎 `services/capability_assessment.py`，无 LLM 依赖）：整体匹配度（**加权均分：专业核心考察点 ×2、通识基础素质 ×1**，体现真实招聘中「专业硬门槛、通识加分项」的取舍；全 1 分 → 20%，全 5 分 → 100%）、专业/通识均分、整体分析、逐维度分析（按分数分段组装针对性文案）、三阶段补步建议（阶段一攻 ≤2 分短板、阶段二攻 3 分中坚、阶段三做 ≥4 分精进与通识转化；各阶段含周期/目标/必学清单/关键动作）、总结与关键提醒、郑重建议、复评日期（约 6 个月后）。
- **记录与排行**：`GET /api/capability/assessments`（历史记录）、`GET /api/capability/assessments/{id}`（报告详情）、`DELETE /api/capability/assessments/{id}`、`GET /api/capability/ranking`（每个岗位取最近一次测评，按匹配度倒序，给出短板维度数与多次测评的变化趋势）。

#### 3.2.6 批量优化 `/batch`
- **定位**：一次针对 1–5 个岗位批量产出优化版本。
- **核心能力**：`POST /api/batch-optimize`（`source_resume_id`+`job_ids[]`，1–5 个）、`GET /api/batch/{id}/status` 查询进度。

### 3.3 记录与投递

#### 3.3.1 面试追踪（枢纽）`/interviews`
- **定位**：求职过程信息枢纽，单页三 Tab 组织：
  1. **投递记录**（ApplicationsTab）——来自 `/api/applications`。
  2. **面试进度**（InterviewProgressTab）——来自 `/api/interview-tracks`，手动录入。
  3. **沟通消息**（CommunicationsTab）——来自 `/api/communications`。
- **联动设计**：投递记录行点「记一笔沟通」→ 自动切到沟通 Tab 并预选该投递（`presetApplicationId`）；手动切 Tab 清空预选，避免重复弹窗。
- **求职时间线（P0）**：投递记录行点「时间线」→ `GET /api/applications/{id}/timeline`，以单条投递为轴聚合三类事件并按时间升序呈现完整求职脉络：起点「提交投递（通道）」→ 投递通道事件（`delivery_events` 全通道流水：入队/送达/退信/预填/平台打开等）→ 沟通消息（`communications` 按 `application_id` 挂靠）→ 面试进度（`interview_tracks` 按 `job_image_id` 精确匹配，无关联时按公司+职位忽略大小写兜底匹配，两分支均限当前用户）。前端弹窗展示合并时间线（分类配色：投递事件按事件类型、沟通按方向、面试按状态）+ 各来源事件计数标签。
- **注意**：投递与面试进度是**两套独立数据**，系统不自动由投递派生面试记录；面试进度纯手动录入，时间线只做只读聚合展示。

#### 3.3.2 投递（一键投递）`/api/applications`
- **定位**：招聘软件式一键投递，只需「选简历 + 选填附言」，联系方式自动带出。
- **核心能力**：
  - 发起投递 `POST /api/applications`（含邮件 / 表单 / 引导 / 手动四类通道，PIPL 单独同意）。
  - 投递列表 / 统计 / 已投递岗位 ID / 单岗位是否已投递 `check/{job_id}`。
  - 投递详情 `GET /{id}`、状态/简历/附言更新 `PUT /{id}`、撤回 `DELETE /{id}`（可发撤回告知）。
  - 投递轨迹时间线 `GET /{id}/delivery-events`。
  - **阶段1 邮件直投**：`contact-hint/{job_id}` 探测 HR 邮箱与通道、后台真实发信、回执同步 `POST /email/sync`、失败重发 `POST /{id}/resend`。
  - **阶段3 官网表单半自动**：`POST /form/probe` 只读探测、`POST /{id}/form/prefill`（202 后台预填，绝不自动提交）、`POST /{id}/form/result` 结果回填。
  - **阶段4 平台引导**：`GET /guide-pack/{job_id}` 准备包、`POST /{id}/guide/opened`、`POST /{id}/guide/result`（最后一步由用户在官方平台手动完成，零合规风险）。
  - **批量投递** `POST /batch`、`/suppressions` 不发送名单（退信自动加入 / 手动加入 / 移除）。
  - 邮件模板 `GET/POST/PUT/DELETE /api/email-templates`。
- **投递按钮文案随通道动态变化（明确系统能力边界，避免过度承诺「一键」）**：弹窗打开后，根据用户在「HR 邮箱 / 官网链接 / 平台引导」中的实际选择，提交按钮文案与顶部「自动化程度」提示实时切换，与后端通道决策优先级（guide > email > form > manual）一致：

  | 用户选择 | 按钮文案 | 自动化程度 | 点击后实际发生 |
  | --- | --- | --- | --- |
  | 勾选「平台引导投递」 | 前往招聘平台投递 | 跳转平台，你手动提交 | 生成准备包（深链 + 简历文本），你前往官方平台完成投递后回来标记结果 |
  | 填写 HR 邮箱 | 邮件直接投递 | 自动完成 | 后台自动把简历发到 HR 邮箱，无需额外操作 |
  | 填写官网投递链接 | AI 帮你填写 | AI 预填，你手动提交 | 打开官网并预填表单，你核对后手动点击提交 |
  | 都不填（仅登记） | 记录这次投递 | 你自行记录 | 仅在本系统登记投递记录，后续动作由你完成 |
- **约束**：`user_id + job_image_id` 唯一（防重复投递，创建前 409）；每日额度（默认 20，`delivery:count:{user}:{yyyymmdd}`）；岗位删除级联清除投递。

#### 3.3.3 面试进度 `/api/interview-tracks`
- **定位**：手动录入的面试进展台账。
- **核心能力**：`GET /options`（公开，枚举）、`POST /` 新增、列表 / 统计（`GET /stats`，可按 status/keyword/start/end 过滤）、详情、编辑、删除。
- **字段**：company/position（必填）、location、stage（笔试/一面/二面/三面/群面/HR面/终面/其他）、mode（现场/线上/电话）、interviewer、interview_time、status（scheduled/awaiting/passed/offer/rejected）、result、可选关联 resume_id / job_image_id（快照）。

#### 3.3.4 沟通消息 `/api/communications`
- **定位**：用户与某公司就某次投递的往来记录（电话 / 邮件 / 微信 / 其他）。
- **核心能力**：`GET /options`（公开）、`POST /` 新增（可关联投递自动带出公司 / 职位；未关联且无公司名 → 422）、列表（可按 application_id/company/keyword/direction 过滤）、统计、详情、编辑、删除。
- **与站内消息隔离**：与 `/api/messages` 相互独立，不重复写入；邮件回执经 `email/sync` 生成的是 `communications`（方向 `in`），**不是** `/messages`。

#### 3.3.5 历史记录 `/history`
- **定位**：优化记录的时间线列表，可查看 / 对比 / 重新导出 / 进入详情。

#### 3.3.6 回收站（跨模块）`/recycle`
- **定位**：简历 / 岗位 / 优化记录三类资源的统一回收站入口。
- **核心能力**：各模块均有 `trash`（列表）、`restore`（恢复）、`batch-restore`、删除（永久）接口；软删除后数据仍可展示（快照），恢复即可回到原列表。

### 3.4 协作与系统

#### 3.4.1 站内消息中心 `/messages`
- **定位**：系统通知（审批、提醒等）中心，独立于投递沟通。**唯一权威消息中心**：顶栏铃铛与「我的 → 消息中心」均指向本页，不再存在第二套重复的消息管理 UI。
- **核心能力**：`GET /api/messages`（分页 / 未读筛选）、标记已读（单条 / 全部）、删除；支持按类型（系统 / 简历优化 / 面试追踪 / 职位动态 / 活动 / 评分）筛选、消息统计与通知设置。
- **统一入口**：① 顶栏铃铛 = `Dropdown` 预览面板（展开显示最近消息 + 未读数，「全部已读」与「查看全部消息」跳转本页），彻底修复此前「点击无响应」；② 「我的」页保留「消息中心」Tab，但仅作**预览 + 进入按钮**（展示最近 5 条与未读角标，点击进入本页），所有增删改与分类管理只在 `/messages` 进行，杜绝两处数据不一致。

#### 3.4.2 全局搜索（顶栏）
- **定位**：跨简历 / 岗位 / 优化记录聚合检索，输入防抖 350ms，结果分组跳转。
- **核心能力**：`GET /api/search?q=&limit=` 返回 `{resumes, jobs, optimizations}` 三组。

#### 3.4.3 管理员后台 `/admin`
- **定位**：运营与配置控制台（独立 admin JWT）。
- **核心能力**：`POST /admin/login`；用户管理（列表 / 详情 / 封禁 / 解封 / VIP / 额度）；简历模板、行业关键词、ATS 规则 CRUD；Prompt 版本管理与（灰度）部署 / 回滚；模型列表 + 调用日志；任务监控（总览 / 失败 / 重试）；数据大屏（核心 / 行业 / 匹配分趋势 / 功能使用 / 岗位热度 / 满意度）；订单 / 退款 / 营收 / 套餐；满意度反馈与聚类；工单（列表 / 详情 / 回复 / 状态）；操作日志。
- **已知未接入**（技术债）：Prompt 模板与模型路由尚未进入优化业务链路；异步任务执行仍在 Web 进程内（`asyncio.create_task`），但已具备**可靠任务队列三重保障**（见下），多进程部署时可平滑演进为 arq/Celery worker。

#### 3.4.4 认证与安全 `/api/auth`
- **定位**：账号体系。
- **核心能力**：邮箱 + 验证码注册 / 登录（双 Token）/ 刷新 / 退出（吊销设备）/ 忘记密码（发码 + 重置）/ 改密码 / 设备管理（列表 / 下线）/ 绑定解绑手机 / 注销账号（30 天冻结期）。
- **安全**：PII 加密与日志脱敏；文件仅签名代理 URL 访问；对外投递强制 PIPL 单独同意；退信自动进抑制名单。

## 4. 功能模块关系图（数据流转）

```
                 ┌──────────────┐         ┌──────────────┐
                 │  简历管理     │         │   岗位库     │
                 │ /resumes     │         │   /jobs      │
                 └──────┬───────┘         └──────┬───────┘
                        │ parsed_json            │ parsed_job_json
                        ▼                        ▼
        ┌───────────────────────────────────────────────────┐
        │            简历优化核心链路 /optimize               │
        │  (解析→AI优化→渲染PDF/Word；评分/匹配/ATS/分析)      │
        └───────┬───────────────┬───────────────┬───────────┘
                │               │               │
                ▼               ▼               ▼
         历史记录/导出      人岗匹配罗盘      岗位热度趋势
                          ATS体检/评分

        岗位库 ──(一键投递)──▶ 投递 /applications ──┬──▶ 邮件直投(阶段1) / 官网表单(阶段3) / 平台引导(阶段4)
                                                  │
                                                  ▼
                                    面试追踪枢纽 /interviews
                                    ├─ 投递记录 Tab  (来自 applications)
                                    ├─ 面试进度 Tab  (interview_tracks, 手动)
                                    └─ 沟通消息 Tab  (communications, 可关联投递快照)
                                                  ▲
                              email/sync 回执 ────┘ (退信→suppression；回复→communications in)

        首页洞察 ◀── 聚合(简历/岗位/优化/投递/进度)     站内消息中心 /messages（独立）
        全局搜索 ◀── 跨(简历/岗位/优化)
```

**关键依赖关系**
- 优化 / 匹配 / ATS / 评分 / 分析 均依赖 `resume.parsed_json` 与 `job.parsed_job_json`；未解析会统一报错（如 `PARSE_BEFORE_OPTIMIZE` / 400「尚未解析」）。
- 投递 → 岗位（`job_image_id` 外键，岗位删除级联清除投递；撤回释放唯一约束）。
- 沟通 → 投递（`application_id` 可选外键，投递撤回时 `SET NULL` 仅解除关联、保留沟通内容）。
- 投递 ↔ 站内消息：二者互不直接写入；HR 邮件回复经回执同步写入 `communications`，不写入 `/messages`。

## 5. 角色与权限

| 角色 | 范围 | 入口 |
| --- | --- | --- |
| 普通用户 | 全部业务功能，仅可见本人数据 | Bearer access token |
| 管理员 | `/api/admin/*` 全部运营与配置 | 独立 admin JWT（`POST /api/admin/login`） |
| 匿名 / 公开 | 仅下列接口无需登录：`/api/auth/*`（注册/登录/刷新/找回）、`GET /api/jobs/categories`、`GET /api/interview-tracks/options`、`GET /api/applications/options`、`GET /api/communications/options`、`GET /api/files/{key:path}`（仍需有效签名）、`POST /api/admin/login` |

**越权防护**：投递 / 沟通 / 面试进度 / 简历 / 岗位接口均按 `user_id` 过滤，跨用户访问返回 404 或空结果。

## 6. 关键通用机制

| 机制 | 说明 |
| --- | --- |
| PIPL 单独同意 | 任何对外投递（邮件 / 官网表单 / 平台引导）必须 `consent_given=true`，否则 422 拦截。 |
| 每日投递额度 | 默认 20 封/天，Redis 计数 `delivery:count:{user}:{yyyymmdd}`；单投与批量共享，耗尽返回 429。官网表单与平台引导**不占用**邮件额度。 |
| 防重复投递 | `user_id + job_image_id` 唯一约束 + 创建前 409 拦截；撤回后约束释放可重投。 |
| 退信抑制名单 | `email/sync` 检测到退信自动加入 `suppressions`；后续同邮箱投递被 422 拦截；可手动移除恢复。 |
| 文件签名 URL | 文件不挂静态目录，仅经 `GET /api/files/{key:path}?exp=&sig=` 限时访问。 |
| 软删除 / 回收站 | 简历 / 岗位 / 优化记录走软删除，进回收站可恢复；投递 / 沟通 / 面试进度为硬删或按需保留。 |
| 通道决策优先级 | 显式 `channel_hint=guide` > 邮件（有邮箱+授权）> 官网表单（有 apply_url+授权）> 手动记录。 |
| 降级与兜底 | LLM 无 Key → Mock（仅 development；production 显式报错防「假结果」）；PDF 渲染 Playwright → WeasyPrint → ReportLab；SMTP/IMAP 未配置 → `dry-run`（不真正出网，仍落事件）。 |
