# 鉴权门与静默刷新修复说明（2026-10-25）

## 问题现象

重启服务 / 离开一段时间后打开前端：

1. **先显示「优化主界面」几秒，再跳转到登录页**；
2. access token 一过期（TTL 120 分钟）就被迫**完整重登**，「记住我 7 天」从未生效。

## 根因（Playwright 四态实测 + 全 src 穷举确认）

1. 鉴权写在每个页面的 `useEffect` 里：`const t = getToken(); if (!t) router.push('/login')`。SSR 阶段 token 恒为 null，服务端先吐出 AppLayout 外壳 + 骨架屏 HTML（用户感知为「优化主界面」），hydration 完成后才跳转；dev 冷启动 chunk 慢 → 「几秒」可见。
2. access token TTL 仅 120 分钟（`ACCESS_TOKEN_EXPIRE_MINUTES`），「离开一段时间」必过期。
3. **真 bug**：`getToken()` 检出过期时直接 `clearAuth()`，把 7 天有效期的 refreshToken 一并删除——每次 access 过期都丢失续期凭证。

## 修复（A：全局鉴权门 + B：启动静默刷新 + C：middleware 服务端前置鉴权）

### A + B（2026-10-25 首批，commit `c0ba2c7`）

| 组件 | 职责 |
| --- | --- |
| `src/components/AuthGatekeeper.tsx`（新） | 挂在根 layout 最外层。未裁决前只渲染全局 loading（`data-testid="auth-gate-loading"`），**children 一律不挂载**——业务页骨架再也不会先于跳转出现（SSR/CSR 首帧一致，无 hydration mismatch） |
| `src/lib/auth.ts` | 分离 `isTokenExpired`（纯判断）与清除；`getToken()` 过期只返回 null **不清除**；新增 `getRefreshToken`。清除只发生在刷新失败 / 主动登出 |
| `src/lib/api.ts` | 导出既有单飞 `refreshAccessToken`（成功双 token 轮换写回，失败清场不跳转）供门复用，零新增刷新逻辑 |
| `src/app/layout.tsx` / `globals.css` | 门挂载 + `.auth-gate` loading 样式（fixed 定位，`--bg-body` 适配暗色） |

**门裁决流程**：公开路径（`/login` `/register` `/forgot-password` `/admin`，admin 有独立 token 体系）直接放行 → access 有效放行 → access 过期但 refresh 在有效期内 → 静默刷新成功后放行 → 失败/无凭证 → `clearAuth()` + `router.replace('/login')`（replace 不污染历史栈，返回键不闪回）。

**设计要点**：
- `decided` 一旦置 true 不回退：首屏挂载必从 false 开始裁决；已放行后业务区间导航无需重裁（token 若在别的标签页失效，由 api.ts 的 401 拦截器收口——清场硬跳 /login，整页刷新后门重新裁决）。
- children 未裁决不渲染 ⇒ 18 个页面自带的 `if (!t) router.push('/login')` 兜底逻辑**天然不会与门竞态**（页面挂载时 token 必然已有效），老代码零改动。
- refresh 单飞去重：门与 401 拦截器共用同一 Promise，并发只发一次 `/api/auth/refresh`。

### C：middleware 服务端前置鉴权（第二批）

| 组件 | 职责 |
| --- | --- |
| `frontend/src/middleware.ts`（新） | 服务端前置鉴权：只判「有无登录票」（cookie 镜像 `sr-token` / `sr-refresh`），无票 → 307 跳 `/login?next=原路径`，**业务页 HTML 不出厂**，从源头消灭「先闪业务骨架再跳登录」的服务端残余窗口 |
| `auth.ts` cookie 镜像 | `setAuthTokens(token, refresh)` 统一写入口（localStorage + cookie 同步）；`syncAuthCookie()` 兜底补票；`clearAuth()` 连带清 cookie。cookie：非 httpOnly、`Max-Age=7 天`（与 refreshToken TTL 对齐——**绝不能设成 access 的 2 小时**，否则浏览器停止发送 cookie，middleware 会把「过期但可刷新」的用户误踢去登录，破坏 B）、`SameSite=Lax`、https 时加 `Secure` |
| `login` / `qq-callback` / `register` / `api.ts` refresh | 四处登录态写入全部改走 `setAuthTokens` 统一入口（此前各自 `localStorage.setItem`，无 cookie 同步） |
| `login` 页 next 闭环 | 消费 `?next=` 参数，登录成功/已登录自动弹回落回原深链；`safeNext` 校验（仅站内相对路径，防开放重定向） |

**A/B/C 分层协作**（关键设计）：

```
浏览器请求业务页
  └─ middleware（C）：有票？─否→ 307 /login?next=…（HTML 不出厂）
                          └─是→ 放行
       └─ AuthGatekeeper（A）：SSR 只吐全局 loading，未裁决 children 不挂载
            └─ decide（B）：access 有效？─是→ 放行
                            └─否→ refresh 有效？─是→ 静默刷新后放行
                                              └─否→ clearAuth + replace('/login')
```

- middleware **不做 JWT 过期判断**（只判存在）：过期续期完全交给客户端门。若 middleware 按 exp 提前跳登录，「过期但可刷新」的用户会被误踢，B 的 7 天免登录被破坏。
- `syncAuthCookie()` 兜底：存量用户（上线前登录的，有 localStorage 无 cookie）被拦到 /login 后，门在 /login 放行前补票 → login 页「已登录自动弹回」→ 目标页 middleware 放行，**不会形成「拦截→弹回→再拦截」死循环**。

## 输入输出与外部契约

- 无新端点：复用 `POST /api/auth/refresh`（入参 `{refresh_token}`，返回 `{access_token, refresh_token, user}`，服务端双 token 轮换 + 设备表换 hash）。
- 无新存储键：localStorage 仍用既有四键（`token`/`refreshToken`/`user`/`deviceId`）；新增 **cookie 镜像两键**（`sr-token` / `sr-refresh`，Max-Age 7 天）仅供 middleware 读取，JS 侧可读可清（与 localStorage 同安全水位）。

## 遗留 / 后续选项

- 生产构建（`next build && next start`）后 hydration 从秒级降至毫秒级，loading 窗口进一步收缩。
- 若未来要上 httpOnly cookie（更高安全水位），需同步改造：middleware 已能读 httpOnly cookie，但登出需改由服务端端点清 cookie（JS 删不了 httpOnly）。
