# 官网表单半自动投递——合规核查清单（通道 B）

> 版本 v1.0 ｜ 2026-09-20 ｜ 对应阶段3 实现（`backend/app/services/form_delivery.py`、
> `app/api/applications.py` 的 `/form/*` 端点、`scripts/verify_form_delivery.py`）

## 一、设计边界（红线）

| # | 红线 | 实现保障 |
|---|------|----------|
| 1 | **绝不自动提交**：系统只预填，提交必须由用户在浏览器中亲眼核对后手动点击 | `prefill_on_page` / `open_and_prefill` 全程无点击提交代码路径；回归脚本内置本地测试站点，断言预填后服务器**零次**收到 `/submit` |
| 2 | **robots.txt 核查前置**：目标站点 Disallow 命中时拒绝探测与预填 | `check_robots_allowed` 以独立 UA + 通配 UA 双重核查；禁止时 probe 返回 `ok=false`，预填直接中止并落 `form_failed` 事件 |
| 3 | **PIPL 单独同意**：向官网提交简历属对外提供敏感个人信息 | 创建 form 通道投递必须 `consent_given=true`，勾选框文案明确「提交至官网投递页面」，授权时间快照落库（`consent_at`） |
| 4 | **数据最小化**：仅预填投递必需字段 | 预填字段白名单：姓名/邮箱/电话/附言/简历附件；无法归类的字段（kind=other）不预填 |
| 5 | **探测只读**：表单结构识别阶段不提交任何数据 | `probe_form_page` 仅 GET 页面 + robots.txt，无任何 POST |
| 6 | **用户控制权**：结果由用户回填（已提交/未完成），可撤回投递记录 | `/form/result` 回填端点 + 撤回（硬删，同其它通道） |
| 7 | **不逆向、不绕过**：不破解 ATS 鉴权、不伪造登录态、不绕过验证码 | 预填仅在公开可达页面上执行；页面 4xx/动态渲染识别不出表单时如实提示，不尝试绕过 |

## 二、上线路前核查项（每次面向公众前过一遍）

1. **UA 与身份**：当前 UA 为通用浏览器 UA。若后续加入自定义 UA（如 `SmartResumeBot`），需在站点 robots 处核对该 UA 的规则集（代码已按「先专用 UA、再通配」双重核查，天然兼容）。
2. **频率控制**：表单投递不占邮件每日额度（不发邮件），但仍受同一岗位唯一投递约束。若未来开放批量表单投递，须先加入频率上限（建议 ≤5 次/日）并显著降低并发。
3. **ATS 差异**：Moka/北森/Greenhouse 等多为 SPA 动态渲染，静态探测可能识别不出字段——此时产品如实提示「请在浏览器中手动填写」，不得注入脚本强行匹配。
4. **凭证与登录墙**：跳转后要求登录的 ATS 页面一律止步，提示用户自行登录后手动完成。
5. **日志脱敏**：`delivery_events.detail` 只记录数量类摘要（已预填 N 个字段），不落用户 PII 原文。
6. **留存期限**：投递记录与事件遵循项目整体保留策略（默认 2 年或注销即删）。

## 三、已识别的残留风险

- **robots 只覆盖"抓取"语义**：robots.txt 限制的是爬虫抓取，用户驱动的表单提交不在其约束范围。本项目仍将 robots 作为探测阶段的从严前置（超出法定要求），但**不能**据此宣称获得站点授权。
- **目标站点 ToS**：部分 ATS 平台用户协议禁止自动化工具。半自动形态（用户在场、手动提交、无脚本注入）风险显著低于全自动，但商业化前建议逐家核对主流 ATS 的 ToS 条款。
- **验证码**：遇到验证码即止步（不识别、不绕过），由用户手动完成后继续——当前实现天然满足，无代码路径可绕过。

## 四、验收标准对照（实施计划 阶段3）

| 计划验收项 | 状态 |
|---|---|
| 表单结构识别 | ✅ `probe_form_page`：robots 核查 + 字段分类（name/email/phone/cover_letter/resume_file） |
| 本地浏览器半自动填充 | ✅ `open_and_prefill`：headed Chromium 预填 + 附件上传，浏览器留给用户确认 |
| 无自动化绕过人工确认 | ✅ 回归脚本断言测试站点零次收到提交；代码无提交路径 |
| 提交结果回填 | ✅ `/form/result`（submitted/failed）→ `delivery_events` + 状态回写；时间线可见 |
| 合规评审清单 | ✅ 本文档 |
