# 多项目共存部署指南（同一台 ECS）

适用场景：智能简历已在 `121.40.191.169` 正常运行，现在要把**另一个项目**也部署到这台机器，共用 80 端口、互不影响。

---

## 0. 先了解现状（部署前必读）

当前架构：

```
外网用户 → :80 → nginx 容器 ──/api/──→ backend:8000（FastAPI）
                        └──────/────→ frontend:3000（Next.js）
其它服务：db(5432) / redis(6379) / celery_worker，均不对外暴露
```

关键事实：

| 项 | 值 | 说明 |
|---|---|---|
| 唯一入口 | nginx 容器占宿主机 `80` | 新项目**不能再映射 80** |
| compose 网络 | `smart-resume_default` | 新容器加入它才能被 nginx 反代（用 `docker network ls` 确认实际名字） |
| 容器 DNS | `127.0.0.11` | nginx 反代必须用「resolver + 变量」模式，见第 5 节 |
| 安全组 | 只放通 TCP 80 | 新项目外网访问也必须走 80 |
| 机器资源 | 2 vCPU / 8 GiB | PG+Redis+后端+前端约占 2~3G，新项目别太重 |
| nginx 配置位置 | 宿主机 `/opt/smart-resume/docker/nginx.conf` | bind mount 进容器，改宿主机文件即生效 |

总原则：**新项目的容器只加入内部网络，不占宿主机端口；对外一律由 nginx 反代。**

## 1. 场景 A：新项目也是 Docker 化的 Web 应用（最常见）

以新项目 `/opt/myapp`（自己的 compose）为例，走**子路径** `http://121.40.191.169/myapp/`。

### 1.1 上传代码（同智能简历的打包法）

本地 CMD / Git Bash：

```cmd
tar --exclude=node_modules --exclude=.next --exclude=.venv --exclude=__pycache__ --exclude=.git --exclude=.env -czf D:\myapp.tar.gz .
scp D:\myapp.tar.gz root@121.40.191.169:/root/
```

服务器：

```bash
mkdir -p /opt/myapp && tar -xzf /root/myapp.tar.gz -C /opt/myapp && cd /opt/myapp
```

⚠️ 项目里的文件名**不要用中文**（Windows tar 会把中文名按 GBK 存包，Linux 解压后变乱码名找不到文件——智能简历的种子数据就踩过这个坑）。

### 1.2 写新项目的 docker-compose.yml

三个要点：**不映射宿主机端口**、**加入智能简历的网络**、新服务只监听容器内端口。

```yaml
services:
  web:
    build: .
    # 不要写 ports! 80 已被 nginx 占用；宿主机端口只留给临时调试且绑 127.0.0.1：
    # ports: ["127.0.0.1:8081:8081"]   # 仅本机 ssh -L 转发调试用，平时注释掉
    restart: unless-stopped
    networks: [shared]

networks:
  shared:
    external: true
    name: smart-resume_default   # 用 docker network ls 看到的实际名字
```

如果新项目自带数据库，同样**不要映射 5432**（会和智能简历的 db 撞），容器间用服务名访问即可。

### 1.3 改 nginx 加反代（核心步骤）

编辑宿主机 `/opt/smart-resume/docker/nginx.conf`，在 `location /api/` **前面**插入（顺序无关，但别插进其它 location 内部）：

```nginx
    # ── 新项目 myapp（子路径方式） ──
    location /myapp/ {
        set $myapp_upstream web:8080;
        proxy_pass http://$myapp_upstream/;      # 末尾斜杠会把 /myapp 前缀去掉再转发
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
```

然后热加载（不用重启、不中断智能简历）：

```bash
cd /opt/smart-resume
docker compose --env-file docker/.env -f docker/docker-compose.yml exec nginx nginx -t
docker compose --env-file docker/.env -f docker/docker-compose.yml exec nginx nginx -s reload
```

访问验证：`curl -I http://121.40.191.169/myapp/`。

### 1.4 启动新项目

```bash
cd /opt/myapp
docker compose up -d --build
```

注意 `exec nginx nginx -t` 显示 `test is successful`、reload 显示 `signal process started` 才算成功。

## 2. 场景 B：新项目用独立域名（有域名时）

假设新项目域名 `app2.example.com` 已 A 记录解析到 `121.40.191.169`。

nginx.conf 里**新加一个 server 块**（不要动现有 server）：

```nginx
server {
    listen 80;
    server_name app2.example.com;

    location / {
        set $myapp_upstream web:8080;
        proxy_pass http://$myapp_upstream;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

同样 `nginx -t` + `nginx -s reload`。之后可以在阿里云申请免费证书配 HTTPS（照抄智能简历的 `docker/nginx-https.conf` 改 server_name 和 upstream）。

没有域名就只有 IP，用场景 A 的子路径方式（`server_name _` 已兜住所有 IP 直接访问）。

## 3. 场景 C：纯静态网站

两种做法，推荐第一种：

### 3.1 nginx 直接托管目录（零容器）

```bash
mkdir -p /opt/static-site && cd /opt/static-app
# 上传静态文件到此目录（tar+scp 同上）
```

nginx.conf 加：

```nginx
    location /site/ {
        alias /opt/static-site/;      # 静态目录在宿主机，但 nginx 是容器——见下方注意
    }
```

⚠️ **nginx 跑在容器里，看不到宿主机路径**。要么给 nginx 容器加 bind mount（改 compose 的 nginx volumes：`- /opt/static-site:/usr/share/static-site:ro`，然后 `up -d nginx` 重建），要么用 3.2。

### 3.2 静态服务容器（推荐，不碰现有 compose）

```yaml
# /opt/static-site/docker-compose.yml
services:
  web:
    image: nginx:1.27-alpine
    volumes:
      - ./html:/usr/share/nginx/html:ro
    restart: unless-stopped
    networks:
      shared:
        external: true
        name: smart-resume_default
```

然后按 1.3 的方式加 `location /site/` 反代 `web:80`。

## 4. 数据库怎么安排

| 方案 | 做法 | 适合 |
|---|---|---|
| **复用智能简历的 PG**（推荐，省内存） | `docker compose exec db psql -U postgres -c "CREATE DATABASE myapp"`，新项目 `DATABASE_URL=postgresql://postgres:密码@db:5432/myapp`，加入 `smart-resume_default` 网络 | 中小项目 |
| 新项目自带 DB 容器 | 自己 compose 里写 db 服务，**不映射宿主机端口** | 需要不同 PG 版本/隔离 |
| SQLite / 无数据库 | 卷挂载数据目录即可 | 小工具 |

密码规则同智能简历：仅大小写字母+数字+`-_`（密码会进 DATABASE_URL，禁 `/ & ' \ @ : # ? %` 空格）。

## 5. 必须避开的坑（都是本项目实际踩过的）

1. **nginx 反代必须用 resolver + 变量**：直接写 `proxy_pass http://web:8080`（或 upstream 块）会在 nginx 启动时解析一次 DNS，新容器一旦重建换 IP 就 **502**，且每次后端更新后都要手动重启 nginx。正确写法照抄第 1.3 节的 `set $var 容器名:端口` 模式。
2. **宿主机 80 只有一个**：新项目无论映射多少端口，外网都只认 80 → 必须走 nginx 反代；`docker compose ports` 映射 `80:80` 会直接启动失败（端口冲突）。
3. **前端构建期变量要填公网地址**：Next.js 的 `NEXT_PUBLIC_API_URL` 会被内联进浏览器 bundle，填 `http://web:8080` 浏览器打不开，必须填 `http://121.40.191.169/myapp` 或正式域名。
4. **中文文件名不进包**：Windows tar 中文名 = GBK 字节，Linux 解压乱码（种子数据事故）。对外交付文件一律英文名。
5. **.env 不上传**：tar 排除 `.env`，服务器上用模板重新生成；密钥不随包走。
6. **改 nginx.conf 后必须 `nginx -t` 再 reload**：配置写错直接 reload 会让 nginx 用旧配置继续跑（或退出），`test is successful` 才是安全信号。
7. **内存**：`docker stats` 看总占用，2C8G 上新项目超过 ~2G 就该升级 ECS 或拆机器。
8. **compose 项目名冲突**：两个项目目录名不同，compose 自动以目录名做项目名前缀，容器名不会撞；但**卷名**如果都叫 `pgdata` 也不会撞（同样有项目名前缀）。

## 6. 一页速查（新项目上线清单）

```bash
# 服务器上执行顺序：
mkdir -p /opt/myapp && tar -xzf /root/myapp.tar.gz -C /opt/myapp
# 1) 新项目 compose：不映射宿主机端口 + 加入 smart-resume_default 网络
cd /opt/myapp && docker compose up -d --build
# 2) nginx 加 location / server（resolver + set 变量模式）
vi /opt/smart-resume/docker/nginx.conf
# 3) 校验 + 热加载
cd /opt/smart-resume && docker compose --env-file docker/.env -f docker/docker-compose.yml exec nginx nginx -s reload
# 4) 验证（智能简历 + 新项目都要测）
curl -s http://127.0.0.1/health
curl -I http://127.0.0.1/myapp/
```

日常维护命令：

```bash
# 各项目容器状态
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
# 新项目日志 / 重启 / 更新（和智能简历同样的套路）
cd /opt/myapp && docker compose logs --tail=50 web
cd /opt/myapp && docker compose up -d --build
# 确认网络名字（换机器/重装后核对一次）
docker network ls
```

## 7. 什么情况下不建议共存

- 新项目是**重资源应用**（Java 巨无霸、训练任务、视频处理）→ 2C8G 扛不住，直接买第二台 ECS
- 新项目需要**独立的安全边界**（不同团队、等保要求）→ 分机器
- 新项目**端口策略特殊**（要对外开 22/3306/6379 等）→ 别在智能简历的机器上开，安全组只放 80 是当前基线

以上情况外，同一台 ECS 按本指南共存完全没问题，nginx 一个入口管所有。
